# Interface

Daybook's interface follows one idea: **a conversation is a page**. You open it to a calm, typeset document. It has the title, one byline, what happened, the next steps, the template's sections, and then your own notes with their recording times in the margin. The transcript is the evidence behind the page: one switch away, with the same margin of times. The window around the page is a frame, not a feature list.

The redesign was planned from UX, platform (macOS 26/27 Human Interface Guidelines and Liquid Glass), and wearable-companion research, and then two competing design directions. This document records the result so future changes stay consistent.

## Principles

1. **One thing on screen per moment.**
   - During a call: a notepad, Bookmark, and Stop.
   - Afterwards: the gist and the next steps.
   - Weeks later: search that opens at the exact passage.
2. **Status speaks only when there is something to say.**
   - When everything is fine, nothing reports status.
   - Working or needing attention shows one line in place: in the page, and in the list row.
   - A working state is a bare line. A state that needs the person is a quiet filled box with at most two actions.
   - Processing is never a toolbar button. It starts by itself after recording and import, and reprocessing lives in menus.
3. **Chrome is a frame.**
   - The main toolbar shows at most three groups plus search, and never overflows at 1280 pt. Its groups never come and go: what doesn't apply is dimmed, so Record stays under the pointer.
   - Liquid Glass appears only on the control layer: the system toolbar, sidebar and inspector, and the player capsule.
   - Content is never glass.
   - Chrome uses system semantic colours only (so vibrancy, Increase Contrast and inactive windows keep working). Paper uses the Ink scale.
4. **Colour has a job.** Neon marks what is live or what you can act on, in dark mode, at small sizes. Each colour means one thing:

   | Colour | Means | Appears |
   |---|---|---|
   | Red (`Ink.record`) | Recording, right now | The recording dot in the byline and list row; the Floating Notes clock; Stop (panel and toolbar pill); the Record button's dot. |
   | Amber (`bookmark`) | Something you marked | Bookmark glyphs, the transcript's bookmark label and 2 pt rule, count badges. Nothing else. |
   | Teal (`accent` fills / `Ink.link` text) | Selected, or you can act on it | Selection, focus, checkboxes, every link and text button in content, tag chips, the play pill, the transcript note rule, "Saved ✓". |
   | Neon mint | Playing now | Playhead rule and wash, slider, play button, byline waveform, a recorder's Listening waveform (both Dark Mode; link ink in Light, `DaybookStyle.liveGlyph`). Inserted words in Version History. |
   | Brand gradient (mint → cyan → violet) | Daybook itself, or work in progress | Mark, Welcome bullets, the Settings privacy lock, progress bars (including the 2 pt line in a list row that is transcribing). |
   | Orange (`Ink.warning`) | Needs you | Failure glyphs, problem boxes, "Recording stopped", "No conversations". |
   | Speaker inks | A person | Speaker names, owner chips, inspector dots and bars. |

   System blue never appears in content: text links use `.buttonStyle(.daybookLink)`.
5. **Nothing a person reads on paper goes below 4.5:1.** Only placeholders and disabled text (`Ink.faint`) are exempt. Chrome never puts a time, a control, or a preview in `.tertiary`.
6. **Facts, not slogans.** Privacy and provenance appear where a reader expects them. "Summarized on this Mac · Gemma 4 · E4B · 31 Oct, 10:02" (or "on Studio Mac", "on this iPhone", or "with Claude Sonnet 5.5" with a cloud glyph: where it ran, the model, and when; the glyph is the device's kind, this Mac's read from its hardware so a MacBook is a laptop whatever its name) sits at the foot of the page on both apps (DaybookKit's `SummaryColophon`), and the full statement is in Settings › Library.
7. **Say what's happening, not how it works.** No subtitle, footer, notice, or empty state explains mechanics: sync, iCloud, the Wi‑Fi link, where audio travels, which model runs where, or what Daybook never does. Keep status values, a next step that matters, a problem and its fix in one short sentence, and a destructive action's consequence; prefer a label to a sentence, and explanation belongs only in Welcome.

## Window structure

- **Main window** (`Window`, id `library`): a three-column `NavigationSplitView`.
  - **Sidebar:** All Conversations, Work, and Personal, then Folders (once one exists), then Trash (once something is in it), then Devices (once a recorder is added; see [devices.md](devices.md)). There are no counts and nothing pinned to the bottom.
    - Rows use `SidebarLabelStyle`: every symbol centred in one column, then the title. It follows System Settings › Sidebar icon size: column 16 / 20 / 24 pt, symbol 12 / 15 / 18 pt, gap 6 / 7 / 8 pt (small / medium / large). Row height, selection and icon tint stay the system's.
    - Section headers start on the icon column's edge; their `+` appears on hover (11 pt semibold, 20 pt hit area).
    - Conversations dragged onto Work, Personal, or a folder are filed there, and onto the Trash asked about first. Each row is its own drag source, as `ConversationTransfer`: the conversation inside Daybook, its Markdown as a file or its title and gist as text outside it; ⌘C copies the same. A row dragged from a selection of several files the whole selection (`ConversationDrop`); out of Daybook it carries its own conversation. Share… sends `ConversationShareItem`, the Markdown or the words without the in-app type. Filing, a folder made, renamed, or deleted, and tags can be undone (Edit › Undo, `LibraryController+Filing`).
  - **List column:** rows grouped Today / Yesterday / Previous 7 Days / Previous 30 Days / months / years: the title, then the date and the gist, then the conversation's tags when they fit. The row is DaybookUI's `ConversationRowView`, the iPhone's and Floating Notes' Recent too.
    - The date reads in `.primary`, the preview in `.secondary`. A first note line that repeats the title is skipped. VoiceOver reads what the row shows: title, date, length, then the gist or what's happening in its place, and the tags.
    - A trailing glyph appears only when a conversation isn't ready: recording, transcribing (a 2 pt gradient line), waiting, waiting for models, paused, couldn't finish, or not transcribed; mint while it plays; and when its work finishes, the done mark for 1.5 s. Its words are DaybookKit's `ConversationStatusPresentation.row`, on both apps.
    - The column's subtitle speaks only while work is happening. An empty place says "No Conversations" (a folder adds how to fill it); an empty library says so once, on the page, and the column stays empty.
    - While sync needs the person, one quiet line sits at the column's top, in the sentence Settings › Library says it with, and Open Sync Settings… (`LibraryWords.syncAttention`; signed out or with iCloud Drive off only on a Mac that has synced).
    - Row menus and the page beside a selection list what `ConversationActions` lists (a selection: Summarize Again, Move to Folder, Tags…, Move to Work or Personal, the Trash), with Share first in a row's menu.
    - Search results start with the scopes (All, Work, Personal, and the folder being viewed: `SearchScopePicker`, the iPhone's too, on one page and two). Then the words found as plain words (a summary's Markdown without its marks), with a title match marked in the title, then matches in saved live captions, labelled "Live captions · tentative", only while the transcript's page shows them (`SavedCaptions.shown`, until a transcript made after them replaces them), and each opens the transcript's page at its caption, on both apps. A passage opens the transcript at it and a note the summary at Your notes (the Mac's `MacSearch.open`, with `SummaryJump`).
    - **Trash** lists what was moved there, newest first, each with Restore in the row and its menu; the page beside it shows the selected one read only, with Restore (`TrashedConversationPage`, the open Duo's right page too). Restoring says so in the notice, with Show.
  - **Detail:** the page, on the Paper reading surface. Teal is the page's tint (checkboxes, links, fills); the toolbar, sidebar, list, and inspector follow the accent chosen in System Settings (the `AccentColor` asset under Multicolor).
  - **Inspector:** hidden by default (⌃⌘I). It's DaybookUI's `ConversationInfoForm`, the iPhone's Info: Details, People, Audio, and Processing, each section collapsing and remembered. Labels and values are one size, labels receding; only the pickers and menus are small. Under a speaker Daybook named by voice, People reads Recognized with Not <name>; under one it's unsure of, Maybe <name> with Yes and No (docs/architecture.md, "Speakers and profiles"); a voice heard only in background audio isn't one of the People (`Meeting.peopleSpeakers`, which the byline names too). When opening it would leave the page under 560 pt, the sidebar steps aside. It shows only where the page keeps 560 pt beside the list (a window of 1140 pt, `ColumnFit`): asking for it in a narrower window (the toolbar, ⌃⌘I, Tags…, the byline's people) widens the window to that, as Finder's preview does, as far as the screen allows, whether or not it was asked for before; otherwise it waits until the window is wide enough. A device's page has none: Tags… and the byline's people there open the conversation in All Conversations with the inspector beside it. On a screen narrower than that, a window as wide as the screen shows it beside a narrower page. macOS's split view won't fold the list column away, so the window makes the room. Tags sit under their label, like Finder's Get Info: a chip shows the conversations with its tag, and its × appears over the chip's corner on hover, so the chip never changes size. Template is a picker whose first item carries the guess ("Automatic (Meeting)"). Folder, Shows in, tags, and a speaker's name can be undone. A recording's menu is `ConversationActions.track` (Play, Adjust Timing…, Show Original Transcript…, Move to New Conversation, Show in Finder, Remove Recording…); Remove Recording… asks first, and a removed recording stays in Audio, dimmed, with Put Back (docs/architecture.md, "Recordings taken out"). Processing's Now row says what's happening in the list row's words, with a summary's choices while it's placed (Use the Cloud, Start Now, Stop), and Don’t Wait while it waits for recordings to come in. On the iPhone, a recording's Adjust Timing… and Show Original Transcript… open in place of Info, as Version History does.
  - The window reopens as the person left it (scene storage, `LibraryRestoration`): the place, the conversation, its page, and the columns they chose to show, each while it's still in the library. The window's own squeeze of a column is never taken for their choice.
- **Detail toolbar:** declared once on the stable detail column (`DetailToolbar`), never inside the per-conversation view. Its groups are always present, dimmed when they don't apply, on a device's page too:
  - Record (the red elapsed-time pill while recording, with its own colours and off the toolbar's shared glass, so it stays red while the window isn't key, as it isn't during a call; Saved with a checkmark for a moment once a recording is saved)
  - the Summary | Transcript switch (disabled until a transcript or saved live captions exist; Bookmark covers its slot, at its width, while that conversation is recording) and More (`ConversationActions`, or on a device's page the device's items)
  - Inspector
  - search

  It isn't customizable: as a customizable toolbar, a window too narrow for its items now and then laid itself out without end at launch (macOS 27.2) and AppKit stopped the app. View › Hide Toolbar (⌥⌘T) is there; Customize Toolbar… isn't.
- **Call prompt:** when a call starts and When a call starts is Ask, a 340 × 108 pt panel in the top-trailing corner of where Floating Notes opens, made as Floating Notes is (non-activating, on every Space and over full-screen apps, out of screen shares): the app's icon, "Zoom call" over the meeting window's title, Not Now and Record (its dot in the recording red, since the panel is never active), and a menu with Always Record Zoom Calls and Never for Zoom. A hairline along its foot drains over 15 s, holding under the pointer. Record grows the panel into Floating Notes' frame in 0.3 s as the recording starts (a fade under Reduce Motion). A call that ends during a recording the person started asks "The Zoom call ended · Stop recording?" the same way, keeping the recording after 30 s. `--call-prompt-demo record|ended` shows either.
- **Floating Notes:** a non-activating `NSPanel` (`.floating`, on every Space and over full-screen apps) that sits over someone else's call without taking focus from it. Panels normally hide when their app is inactive; this one deliberately doesn't, because that is its whole job. It shows your notes and live captions over the call, so it's left out of screen sharing and screenshots (`sharingType = .none`). It's a floating version of the iPhone's main screen: the iPhone's recorder while recording and after Stop (one view on both apps, DaybookUI's `RecorderSurface` and `RecorderAfterStop`), and a small home in the language of its status sheet otherwise. It's one sheet of paper with no glass and no toolbar, so it keeps the smaller titlebar-only corner radius. It opens from Window › Floating Notes (⌥⌘N), the menu bar extra, and the Dock menu: on the recording, else the selected conversation, else its home. The panel and its home are in `Sources/Daybook/UI/FloatingNotes/`; the recorder it shares with the iPhone is in `Sources/DaybookUI/Recording/`, and the notes editor in `Sources/DaybookUI/Notes/` (see Design tokens). Open, a Recent row, a status line, and a chip's Show bring the main window back wherever it is: opened again if it was closed, restored if it was minimized (`openWindow(id: WindowID.library)` from the panel's own environment).
  - **Title band:** the system's title bar (28 or 32 pt, by the system) and 4 pt more, so the phase and the chips have room above and below them (`FloatingLayout.bandRoom`), transparent and without a separator. Close (left) and Compact (right, mirroring it) sit on the band's centre line (AppKit puts close back on every resize; the panel moves it again each layout pass) and fade in only while the pointer is over the panel; minimize and zoom are hidden. Between them, centred like a window title, the phase in the iPhone's words: "● RECORDING · MacBook Pro Microphone" (the input device; "Microphone silent" in `Ink.warning` when the microphone hears nothing, as on the iPhone, with the fix in its tooltip), "✓ SAVED · 18 min" (its length as the page and the list say it, never a time that reads like a clock), or "⚠ STOPPED".
  - **Status chips:** a glyph and a short label in a quiet capsule, each a menu whose first line is the whole status in a sentence (also its tooltip and VoiceOver label), then what you can do. In order:
    - Call (while recording): teal when call audio is detected, calm when it's quiet, and "No call audio" in warning ink with the fix when it should be captured and isn't.
    - Each recorder: "Soundcore · 80%" with the red dot while it records along; "Soundcore on Alex's iPhone" when the iPhone manages it (Use on This Mac in its menu, with Show Soundcore Work); "Moving…" during a handoff; "Not recording" when it was asked to record along and didn't start.
    - Each paired iPhone that's connected or part of the recording: the red dot when it records too, "Alex's iPhone paused" in warning ink when it paused (its menu: "This Mac keeps recording").
    - After Stop, the conversation's processing: "Transcribing · 40%", its pill spanning the row and filling from the left with the brand gradient as the work goes, its words in body ink (another device is named: "Transcribing on Studio Mac · 40%"), "Summarizing in 12 s" while its summary counts down (its menu: Use the Cloud, Start Now), "Summarizing with Claude Sonnet 5.5", "Summarizing…", "Waiting for models", "Summary ready", and "Waiting for iPhone audio" once this Mac's audio is summarized and a recording made alongside it hasn't arrived (docs/multipoint.md, "Mac first"). Its menu pauses, resumes, or tries again.
    - iCloud, only when sync is a problem: "Not syncing", with Open Sync Settings….

    What records along shows only in the chips, at every size, and the iPhone's recorder shows the same chips for the Macs and recorders recording with it (a connected Mac's menu offers Record on Studio Mac Too). Labels shorten, then give way to glyphs, as the panel narrows: a paused iPhone's chip shortens first (to "Paused" by the phone's glyph), a short recorder chip keeps its name ("Soundcore"), and processing and anything that needs you keep their words longest (`RecorderChipFit`). Full, the chips are a row of their own under the band; compact, they share the band with the phase. The recording's words (the phase, the call, each recorder and each other Daybook, the meters) come from DaybookUI's `RecordingStatusWords`, the same words on the iPhone; recorders read as they do everywhere else (`RecorderStatusWords`), and this Mac's queue too (`QueueStatusWords`); the rest come from `FloatingStatus`. All are plain values from plain inputs like the iPhone's `StatusSheetModel` (tests in `FloatingNotesStatusTests` and `RecorderSurfaceTests`). The facts come from `RecordingController.levels` (call detected, microphone silent), the device hub's sessions (connection, battery, recording, `managedElsewhere`), `RecorderHandoff`, `PhoneLink.recordingStates`, the conversation's `CompanionRecording`s, `ProcessingStatus`, `AppState.unexpectedStops`, and the sync status's `problem`. The panel reads them through `FloatingStatusInputs.make` and redraws for what it read; a summary's countdown redraws only its own chip or line, a second at a time. It never reads the meters' levels, which `RecorderLevels` samples on its own timer, so the bar never redraws at meter speed.
  - **Recording:** the title in New York 17 pt (scaling to 1.3× at most); the red elapsed clock (34 pt) beside a rolling meter for each source the recording has now, the iPhone's meter sampled 15 times a second (only the meters redraw); a hairline; your notes with their time lane, each bookmark made while recording an amber tick in the lane beside the paragraph written after it; live captions; and Bookmark and Stop side by side, 44 pt tall.
  - **Meters:** one per source (`RecordingStatusWords.meters`): the microphone (from `RecordingController.levels`), call audio when it's included (the same), each recorder recording along (from the live audio it saves into the recording, `DeviceSession.liveLevel(into:)`), and each iPhone recording along (the levels it sends over the link, `LinkLevels`, played back a reading a tick by `PhoneLevels`). Each row is labelled with its chip's glyph (mic, waveform for the call, the recorder's tape, iphone), with its name in the tooltip and for VoiceOver ("Soundcore Work level"). "Microphone silent" and "No call audio" turn their row's glyph to warning ink, with the fix in its tooltip. A source with no levels yet (an iPhone that doesn't send them, a recorder before its audio arrives, one still starting, a paused iPhone) keeps its row, flat and grey. They share the meter area (`MeterStack`): one source takes it all (40 pt full, 24 compact), two split it as You and Call did (17 and 10 pt rows), more split it down to a minimum row (10 pt full, 8 compact) with the area growing to keep that, up to 56 and 42 pt; past that the rows thin (to 4 and 3 pt) rather than take the notes' room. Glyphs shrink with rows packed too close for them.
  - **Live captions:** a fixed strip above the controls, so the notes never move as words arrive: "LIVE CAPTIONS · TENTATIVE", then the newest two lines, each with You or Call right-aligned in the time lane. The newest is larger and in Body ink, the one above in Secondary, words still being revised in Meta. They're never the transcript.
  - **Bookmark and Stop:** the iPhone's controls (DaybookUI's `BookmarkControl` and `StopControl`). Bookmark is amber with a count pill; it bounces for your own press, never for a bookmark another device added or one taken away, and the count rolls either way. Stop is a red tile with its own colours rather than a system prominent style, so it stays red when the panel isn't key, which is its normal state during a call (and while it saves, "Saving…").
  - **After Stop:** the band says Saved, its checkmark drawn on, and the chips say what's becoming of the recording. The title, when it was, and your notes stay; Open (link teal, "Open Summary" once there is one) takes Bookmark's place and Record takes Stop's, for the next call. A recording that stopped short (nothing reached the conversation, or this Mac's capture stopped on its own: the Mac went to sleep, the disk couldn't keep up) shows "Recording stopped" in a quiet warning box, with why when the recorder knows (otherwise "What was recorded is saved."), and Record Again records into the same conversation, after what was saved, so a call cut short isn't split in two. Recording into it again, from here or anywhere else, ends the stop. A conversation that couldn't finish says so in the words the page uses (`FailureWords`), with Try Again unless there was no speech.
  - **Home** (nothing recording): status lines in the status sheet's language, one each for every recorder ("Soundcore Work  Connected · 80% · 1 new"), every paired iPhone ("Alex's iPhone  Connected"), this Mac's queue while there's work ("This Mac  Transcribing · 40% · 2 waiting"), and iCloud when it's a problem. A line opens its device page. Then Recent: five conversations in the iPhone's row style (the title; the day and what's happening, or the gist; a glyph only when it isn't ready), each opening in Daybook. Opened for a conversation, its title and notes take Recent's place, and "Recent" goes back. Record (a capsule) and Import (a circle) sit at the foot. Record records into the conversation opened here only while it has only notes; one that already has a recording gets a new conversation, so a past call is never added to.
  - **Sizes:** 360 × 560 by default, at least 280 × 196. Below 380 pt tall the panel is compact: the band carries the phase and the chips, then the clock with small meters (four sources fit beside it at every compact size), a line for a note ("Add a note…": Return adds it as a paragraph at its time and clears the line), the newest caption line, and the controls at 34 pt (after Stop, the title and Open and Record; at home, Record and Import). The Compact button snaps to 212 pt and back; dragging the bottom edge does the same.
  - **Grid:** content keeps a 16 pt inset on both sides. Note times and caption sources are right-aligned at x = 44 (fixed 11 pt, so "1:02:03" fits), and text starts at x = 52.
  - **Keys:** ⌘D bookmark, ⇧⌘R stop (or record), ⌘O open in Daybook, ⌘W hide (the recording continues), ⌘+ / ⌘− / ⌘0 text size. There is no Esc binding, so a stray Escape during a call does nothing.
  - **Accessibility:** under Reduce Motion the meters stop scrolling (their bars light from the left up to the level), the clock fades rather than rolls, and surfaces fade. Increase Contrast uses the Ink scale's contrast values and outlines the chips, controls, and Stop; it and Reduce Transparency drop the neon glows. The clock and the meters tell VoiceOver they update often. Each note time is a button for VoiceOver ("Play from 4 minutes 10 seconds") where it plays, or says when the note was taken, and each bookmark tick says itself, beside the notes (the editor's `NotesContainerView` lists them, since a text view reports no children); Play from Here (in the notes' menu and as a VoiceOver action) plays from the paragraph at the insertion point; ⌘F finds in the notes.
- **Menu bar extra:** a standard menu (`.menuBarExtraStyle(.menu)`). Its label is a symbol only, because a ticking text label re-lays out the status item every second. Personal conversations are never named in it ("a personal conversation"). Show Floating Notes (⌥⌘N) opens where Window › Floating Notes does: on the recording, else the conversation the library window shows, else its home. Under When a Call Starts (Off, Ask, Record Automatically), its status speaks only when there's something to say, in the words Floating Notes' home and the iPhone's status sheet use, each item naming what it's about since a menu has no title column (`MenuBarStatus`): this Mac's work ("Transcribing “Weekly product sync” · 40% · 2 waiting", opening it), a summary's countdown as a heading over Use the Cloud and Start Now, a model downloading, a recorder that's moving, importing ("Importing from Soundcore Work · 1 of 3"), listening live, recording, or needs you, with its new recordings ("Soundcore Work · 2 New Recordings…"), each opening its page, a paired iPhone recording or paused ("Alex's iPhone · Paused"), Use on This Mac for a recorder another device manages, and iCloud only as a problem, over Open Sync Settings….
- **Settings** is laid out as System Settings is: a window of its own (`WindowID.settings`; Daybook › Settings…, ⌘,) with its pages in a sidebar with search (General, Recording; Devices, Library; Models, Cloud), each a grouped page, and back and the page's title on one toolbar. Models opens pages of its own: Transcription, Speakers, Summaries, and Model Library (docs/models.md). General has Open at login and the menu bar item; Recording has computer audio, When a call starts (and Apps, for an app with its own answer), Floating Notes, Live Captions, and the permissions; Library has the folder, storage, iCloud Sync, and imports. The search finds a page by its name or what's on it (`SettingsPane.keywords`).
  - **General** has Open at login (`LoginItem`, `SMAppService.mainApp`), off until the person turns it on, since watching for calls and the menu bar item work only while Daybook is open. It's on while System Settings still waits to approve it, with "Allow Daybook in Login Items to open it at login." and Open Login Items Settings… under it (a `ProblemLine`, as is a refusal, with the system's words behind Details…).
  - **Models** is the model manager ([models.md](models.md#the-model-manager)), a grouped form generated from the catalog:
    - Quality: Quick, Balanced, and Detailed as radio rows, each with its models, size, and memory, and this Mac's recommendation marked; Custom appears when the choices match none.
    - A section per role (Transcription with its language rows, Speakers with the speaker settings, Summaries with titles and tags), each with a model pop-up whose items carry their state underneath.
    - Words and Templates.
    - Model Library (disk use, old revisions, updates), then every model grouped by family, ending with Acknowledgements… and Add Model….
    - A row speaks only when something isn't ready: "Not downloaded · 1.6 GB" with Download, "Downloading · 40%" with Cancel. Labels are facts ("Non-commercial", "Added by you", "Recommended"); "In use" and "Update available" are teal because you can act on them; "Needs downloading again" is a warning.
    - Details, Add Model, and Acknowledgements are sheets. Removal is an alert that states what it frees and what each role will use.
    - What the chosen speaker model can't do (matching voices across recordings, a number of speakers) isn't offered, rather than shown dimmed.
  - **Library** is the library's location, iCloud Sync, and the privacy statement (`PrivacyWords.statement`, the iPhone's About's too, by DaybookUI's `PrivacyStatement`) with the version under it ("Version 0.1.0 (1)", `AboutWords.version`, as the About panel and the iPhone say it). iCloud Sync is one row saying where sync stands with its one action ("Up to date · 11:42 AM", Sync Now); a problem follows it once, in place (`ProblemLine`); then encryption and this Mac's preference. Turn Off Sync… and Erase Deleted Conversations from iCloud… sit under the group.
  - **Cloud** is cloud summaries ([cloud](cloud.md#settings)): Keys (each provider's masked key with Replace… and Remove…, or Add Key…, whose sheet checks the key before keeping it, a refused one as a `ProblemLine`), then, once a key is set, Summaries (Use the cloud: Offer First, Always, or Never; Countdown, 15 or 30 seconds, while it offers first) and, unless Never, Quality: Best, Balanced, and Economy as radio rows like Models' presets, each with its recommended model and "About $0.09 an hour"; Model (Recommended or one of the tier's, with its cost when chosen); Effort as a segmented control of what the model takes. The pane's one footer line is "Sends the transcript and notes, never audio." Removing a key is an alert that says it's removed from your other devices too.
  - A problem anywhere in Settings or its sheets is a `ProblemLine`: the warning glyph, one sentence in the label colour, Details…, and its actions, which move under a long sentence.
  - Acknowledgements is DaybookUI's `AcknowledgementsScreen`, the iPhone's (Settings › About › Acknowledgements) too: each model family with its license and required credit (`ModelAcknowledgements.entries`: the models the device can use, the Mac's whole catalog, and those behind the library's results), then Software, the bundled THIRD_PARTY_NOTICES.md and each package's license and notice (`SoftwareNotices`), each opening in place. Esc closes its sheet. The About Daybook panel's credits carry the same models, then the libraries with their licenses.
- **Vocabulary**, **Summary Templates**, and **Speaker Profiles** are separate single windows. Vocabulary and Summary Templates are DaybookUI's screens, the iPhone's Settings screens too ([templates](templates.md)). Vocabulary is a table of Term, Also Heard As, Meaning, and Used In, edited in place (`VocabularyScreen`), 640 pt at its narrowest so the four columns fit. A term from a conversation (a correction, a summary's suggestion) is used only there, "Only “Weekly product sync”", until Used In says All conversations; one whose conversation is gone says "No conversations" in warning ink. Deleting a term used everywhere is at once (Edit › Undo brings it back); deleting one limited to a conversation is "Delete Term…", confirmed with what that conversation loses ("“Weekly product sync” won’t use it when it’s transcribed again."). Search covers the spelling, the other spellings, and the meaning; Show Conversation opens a term's conversation. On the iPhone each term opens its form (Term, Also Heard As with "Other spellings", Meaning, Used In, Delete Term), whose Cancel asks before losing changes and which can't be swiped away with them, and whose Save writes only what the person changed onto the term as the library has it then, so an edit synced meanwhile stays; every change undoes with a shake. Speaker Profiles is DaybookUI's `SpeakerProfilesBrowser`, the screen the iPhone pushes in Settings. It lists each profile with its voiceprints (where each came from: Named, Confirmed, or Learned, with the conversation and date; each removable), Forget Learned Voiceprints…, the conversations it labels (each with its date, opening in the library window), rename, Merge Into (in the profile's menu and beside Delete Profile…, confirmed first: "Merge Vladimir into Vlad?"), and Delete Profile…. A rename to another profile's name stays typed, with "Another profile is called Vlad." and Merge Into Vlad beside it. ## Motion

Animations go through DaybookDesign, so Reduce Motion is honoured the same way on both devices and a curve is tuned in one place:

- `daybookMotion(_:value:)` (`.motion` on both apps) animates with a curve, or `DaybookMotion.reduced` (a 0.15 s fade) under Reduce Motion; `DaybookMotion.resolved(_:reduceMotion:)` does the same for `withAnimation`.
- `daybookTransition(_:)` inserts and removes with its transition, or with a fade under Reduce Motion: nothing slides, scales, or moves then.
- `daybookBounce(value:)` bounces a symbol when something lands; under Reduce Motion it stays still.
- A scroll to a passage animates with `DaybookMotion.scrollAnimation(reduceMotion:)`, which is none under Reduce Motion, so the page jumps.
- A `WorkProgress` bar or line (`.progressViewStyle(.brand)`, `WorkProgressLine`) never animates, whatever animation the change arrives in. A chip's fill is the exception: it moves to each new fraction with `state` (steps under Reduce Motion), and it changes only when the percent does.
- A status line or queue row that counts down (`StatusLineItem.countdownUntil`, "Summarizing in 12 s") redraws only its words, once a second, and its digits roll down (`DaybookMotion.tick`); under Reduce Motion they fade. A countdown is calm: waiting isn't progress.

The curves are `DaybookMotion`'s (`Motion` on the Mac, `PhoneStyle.Motion` on the iPhone): `hover` (0.12 s ease-out), `fade` (0.2 s), `state` (0.25 s snappy), `tick` (0.3 s snappy, rolling digits), `scroll` (0.3 s), `page` (0.35 s), `dim` (0.6 s), and `land` (a spring, for something small arriving); `hold` is how long a done mark stays (1.5 s). Motion only answers something the person did or a change of state. Nothing loops except work in progress and the Listening dot. `MotionAuditTests` lists the curves still written out in views; it reports them for now and fails on them with `DAYBOOK_ENFORCE_MOTION_TOKENS=1`.

### Deliberate departures from Direction A

- Bookmark bounces when added. Direction A said "no bounces"; the bounce confirms an action made without looking, during a call.
- The idle Record button has a red dot, so the one red control is findable before it's needed.
- Next-step owners are chips in their speaker ink, tying a task to the person in the transcript.

## Behaviour worth knowing

- The notes' time margin is drawn by `MarginGutterView`, a subview of the notes text view, on both apps (`MarginNotesEditor`). `NSTextView` clips drawing done in its own `draw(_:)`. It hands VoiceOver an element per time and mark, since the text view is read as one field. The paragraphs it times are split as `NoteTimeline` splits them (`NoteParagraphs`), and a recording's bookmarks and photos sit before the first paragraph written after them.
- Note times come from `Meeting.paragraphTimes()`, which matches the saved anchors to paragraphs by text. A paragraph without a matching anchor shows no time; it never hides everyone else's.
- Times in the interface use `TimeLabel.short` (`0:14`). Model evidence and exports keep `TimeLabel.format` (`00:14`), so summaries aren't affected by display changes.
- A time before the start (a note an iPhone took before the Mac started recording) reads "−0:12", and VoiceOver says "12 seconds before the start" (`SpokenTime`), on both apps. Both count whole seconds toward zero, so what's heard matches what's seen, and less than a second before the start is "0:00".
- Playback is disabled while recording, so computer-audio capture doesn't record it.
- The player is one view on both apps (DaybookUI's `PlayerBar`, over `PlaybackControlling`, which each app's player adopts; both play through DaybookKit's `PlaybackEngine`: one end-of-file rule, seeks held inside the recording, the position read ten times a second on a task of its own). Back 15, Play (mint while playing), Forward 15, the position with the time played and the time left ("−12:03") either side, the speed, an amber Bookmark that bounces when one lands, and Close; of several recordings, which one plays, by its `RecordingWords` name. It takes the room it has: one row; on the Mac then without the skips, then without the speed; then the buttons on a row with the position under them, as every iPhone has it. The Mac's position is the system slider, the iPhone's the `Scrubber`, with a finger's height to grab. While the iPhone's audio downloads, the bar says how far it has got, and when it can't play, why. The skip arrows turn the way they skip at every press, the keyboard's too; under Reduce Motion nothing turns, bounces, or slides.
- The library's notice says each thing on a line of its own. One line can end with a text link that acts on what it says (Undo, Show, Show in Finder: `AppState.post(_:action:)`). The link stays while the notice still says those words, and acting on it takes that line away; the others stay. "Moved “Weekly product sync” to the Trash." ends with Undo, "Recovered “Conversation at 10:15 AM”." with Show, and "Exported Standup.md" with Show in Finder.
- Move to Trash can be undone: Edit › Undo ("Undo Move to Trash", and Redo after it) or the notice's Undo puts the conversations back and selects the first (`AppState.trashMeetings`). The row after them in the list is selected when they go, or the one before at the end, so the person keeps their place. Moving to a folder or to Work or Personal from the menus is undone the same way, named as the menu item was.
- The library window publishes the conversation on its page as `FocusedValues.shownConversation` (the selected one, or on a device's page the conversation of the imported recording it shows), for menus and windows that act on what the person is looking at.
- The menu bar is one `Commands` per menu (`DaybookCommands.swift`). A command for a conversation (File's Export, Show in Finder, Move to Trash…, Add Recording, Add Photos…; Edit's Copy Summary and Paste Photo; View's Summary and Transcript; the Conversation menu) acts on `shownConversation`, so it's disabled while another window is in front or the library window is closed. New Note, New Folder, Record, Import Audio…, a bookmark while recording, Floating Notes, and Search Conversations work from anywhere.
  - Add Bookmark (⌘D) marks the recording's moment while this Mac records; otherwise the player's moment in the conversation on screen when it's loaded there.
  - Controls has Play or Pause (⇧⌘Space; the conversation on screen plays from the start when nothing of it is loaded), Jump Back and Jump Forward 15 Seconds (⌥⌘← and ⌥⌘→), and Playback Speed, the player capsule's speeds.
  - Window › Floating Notes, the menu bar extra, and the Dock menu open the panel by one rule (`AppState.floatingNotesFocus`): on the recording, else the conversation the library window shows, else its home.
- `AppState` and everything it holds (the library, sync, devices, the recorder, multipoint sources, the iPhone link, placements) are `@Observable`: a view redraws for the properties it reads and nothing else, so a sync pass or a progress report redraws only what shows it, and nothing is forwarded by hand. A view takes the state as `let state: AppState`, or `@Bindable` when it binds to it. What's worked out from the library (the visible list, search) is kept until the library's `revision` changes, and reading it follows that revision. Code that isn't a view follows the models with `ObservationWatch`.
- What keeps the window quick while a job runs (measurements in validation.md, 2026-10-29):
  - Progress redraws its views only when the percent, the message, or the step changes (`ActivityProgress`), and progress doesn't animate: the bar and the page's percent step, and a list row fades its line only when its words change (`RowStatus.phrase`). An animation per report kept the main thread drawing frames for as long as a job ran. Only the row being processed reads the job's progress (`AppState.processingStatus(for:)`), and each row and progress line draws in a view of its own (`ActivityReader`), so a report redraws that row and line alone.
  - The app holds `AppState` in `@State` and its scenes only pass it on: the one thing they read is whether a library move holds the library. Read there, every change of the library would rebuild every scene, draw the library window twice, and make SwiftUI write the menu bar item's visibility back to its setting, which redraws every view that keeps a setting. The menu bar item reads the state in its own label, and the setting is written only when it changes.
  - The page and the inspector read the library themselves and are `Equatable` by conversation, so the window redrawing them for the same conversation doesn't draw them again.
  - The transcript page doesn't read the player, whose position moves ten times a second: it follows it apart and redraws when the passage under the playhead changes, on both apps. The Controls menu's Play or Pause reads only whether it's playing.
  - `LibraryController.update` announces a change once (with its time stamp), and not at all when nothing changed. Each announcement redraws every window that shows the library, so batch a change's parts into one `update`.
  - Every list row and status line asks whether this Mac can process (`canProcess`) at every redraw, so the routed models are worked out once per change of what routes them (`routedRequiredModelIDs`). Something new that routing reads belongs in `SpeechRoute.Inputs`.
- A conversation whose kind isn't known yet appears only in All Conversations, never in Work or Personal. The person's placement (`Meeting.placement`) always wins and never changes the template.
- Choosing a different template summarizes again right away. The earlier summary stays in Version History.
- **Where a summary runs** (docs/multipoint.md, "Where summaries run"). With a cloud key, a summary that's due counts down before it starts, in the words both apps share (`SummaryPlacementPlanner.line`): the page's status line says "Summarizing on this Mac in 12 s" with Use the Cloud and Start Now as text links at its end (the iPhone adds Wait for a Mac when it counts down to itself, and says "Summarizing on Vlad's MacBook Pro in 12 s" or "Waiting for a Mac to summarize" with Use the Cloud), then "Summarizing with Claude Sonnet 5.5" with Stop while the cloud works ("· 35%" and the bar once it reports a figure). The list row says "Summarizing in 12 s" with the clock glyph, and so does the list's subtitle while the queue waits on it (in place of "Transcribing 1 of 2"); the iPhone's status sheet counts down in its compact Mac line too; the inspector's Processing repeats the line with its choices, and its Summary row names a cloud model with what it used ("12,700 tokens · $0.05"); Floating Notes' chip and the home's line for this Mac count down too, the chip's menu holding the choices. It's a working state, so a bare line, never a box. Only a countdown redraws each second (`TimelineView`), and only the views that show one observe `AppState.placements`. Summaries someone asked for, and everything without a key, start at once and read as before.
- **Upgrade** (docs/multipoint.md, "Upgrade"). When a clearly better model than the one that made a conversation's transcript, speakers, or summary is within reach, and nothing else is working or waiting, the page's status line offers it, on both apps: the arrow-up glyph, what improves and where ("Upgrade transcript", "Upgrade transcript on Studio Mac", "Upgrade summary with Claude Sonnet 5.5"; the words are DaybookKit's `UpgradeOffer.line`), then Upgrade and Dismiss as text links at its end (on the iPhone, under the words when they need the room). It's optional, so a bare line, never a box, and never in list rows. Once accepted for another device the line reads "Waiting for Studio Mac to upgrade the transcript" until that device starts, with Cancel on the device that accepted it, which takes the request back so the offer returns; once dismissed it goes on every device. The line doesn't explain why the other model is better or where the work runs.
- A title and a bookmark's label are fields with a draft, saved once editing ends (Return, or leaving the field), on both apps: an emptied title puts the old one back, and labels an earlier version wrote by itself read as none. Renaming, ticking a next step, editing a label, deleting a bookmark, and Don't Wait register Undo. ⌘Z puts a renamed title back whole (`LibraryController.update(_:actionName:undoManager:)`); the others it takes back on their item alone, so a bookmark added since, a newer summary, or a recording that arrived on a link stays (`LibraryController+ItemUndo`).
- Version History can put back the text from before a change (notes, a corrected passage, a speaker's name, or a summary), and a deleted photo or bookmark (its entry keeps the whole bookmark, `Meeting.removeBookmark`, and reads "Bookmark deleted", about "Bookmark at 0:14 · Gate on the conflict fix"). The restore is itself a change, so the text it replaces stays in Version History. A conversation's first summary reads "Summary written" and shows on its own, with no empty Before, on both apps (`RevisionText.hasBefore`). The same text changed on two devices at once (a Mac and an iPhone, or two Macs) keeps both versions and reads "Edited on two devices". A summary's Markdown is drawn as the page draws it, bold and bullets with no markup left, and the changed words are marked over it (`RevisionText.styled`, `WordChanges`). On the iPhone a change's page has its kind as the title and, under it, what it's about only when that says more ("Alex → Dana").

## Checking the interface without recording or clicking

Debug builds accept launch arguments that open a specific surface against a separate library with its own preferences:

```
.build/debug/Daybook --library <dir> [options]
  --place work|personal|all|trash|device|device:<name>|folder:<name>
  --select "<conversation title>"     --page transcript     --inspector (or --info, the iPhone's word)
  --search "<query>"                  --sheet history|timing|corrections
  --open-settings general|recording|devices|library|models|cloud
  --cloud-demo none|anthropic|both|never|failed|summary
                                      Settings › Cloud with in-memory keys and the catalog's models (no network,
                                      no keychain); failed opens Add Key with a refused key; summary (with
                                      --library-demo) makes the ready conversation's summary a cloud one
  --open-window vocabulary|templates|speaker-profiles|welcome
  --show-notes   --show-setup (Add Device)
  --device-demo <scenario>            device surfaces with an inert transport; see devices.md
  --simulate-recording "<title>"      fakes the recording state; no microphone
  --notes-after-stop   --notes-hover  Floating Notes as after Stop; with its hover-only chrome showing
  --notes-demo multipoint|paused|processing|stopped|failed|home
                                      Floating Notes states; see FloatingNotesDemo.swift
  --notes-size <W>x<H>                Floating Notes' size, such as 340x228 (compact)
  --notes-open                        closes the main window, then opens the conversation from the panel as Open does
  --notes-contrast                    Floating Notes as Increase Contrast draws it (simulated: the shared tokens and SwiftUI's contrast)
  --play-muted                        plays the selected conversation silently
  --library-demo                      fills the library with conversations in every list, page, and inspector
                                      state, the same ones the iPhone's --library-demo seeds (DaybookKit's
                                      ReadingDemo), with this Mac's queue states on top (LibraryDemo.swift);
                                      --demo-library still works. With it: --inspector-all (every inspector
                                      section open), --multi-select "<title>|<title>", --notice "<text>"
                                      [--notice-action "<title>"] (the notice with its text link on its last line;
                                      lines before it, split by newlines, have none)
  --speaker-demo                      with --library-demo, speakers named, recognized, and suggested, and a second
                                      profile of one person; see SpeakerProfileDemo.swift (the iPhone takes it too)
  --speaker-profile <name> [--profile-name <name>] [--merge-into <name> [--confirm-merge]] [--delete-profile]
                                      with --open-window speaker-profiles: a profile selected, a name typed into it,
                                      a merge asked for (or made), its deletion asked for
  --window-size <W>x<H>               the main window's size, such as 900x700
  --window-actions <step,…>           what the main window goes through before a snapshot, 1.5 s apart:
                                      activate, fullscreen, toolbar, zoom, top, sidebar, inspector (as
                                      Tags… asks for it; full screen needs activate, so run it as an app
                                      with `open`)
  --model-demo <step,…>               Settings › Models states without the network; see models.md. page:<transcription|
                                      speakers|summaries|library> opens one of its pages
  --placement-demo countdown|cloud|colophon|colophon-mac
                                      with --library-demo (or --notes-demo processing), a summary's countdown, the
                                      cloud at work, or a colophon from the cloud or another Mac; see PlacementDemo.swift
  --upgrade-demo mac|here|cloud|waiting
                                      with --library-demo, an "Upgrade" offer on "Offsite retro" (another Mac's, this
                                      Mac's, the cloud's) or one waiting for Studio Mac; see UpgradeDemo.swift. Without
                                      it the library demo offers no upgrades
  --sync-demo <state>                 Settings › Library › iCloud Sync in a state, without iCloud; see SyncSettingsDemo
                                      (paused, account, signed-out, drive-off, waiting, folder-*: the list's
                                      sync line too, SyncAttentionDemo)
  --sync-sheet encrypt|recovery-key|enter-key   with --sync-demo, one of its sheets
  --move-demo <case>                  with --open-settings library, the library move sheet; see LibraryMoveDemo
  --vocabulary-demo   --templates-demo
                                      fill the scratch library's vocabulary or templates (with --open-window; the
                                      iPhone takes them too, with --open-settings vocabulary|templates)
  --login-item-demo approval|refused  with --open-settings general, Open at login waiting for approval or refused,
                                      with a stand-in that never touches this Mac's login items
  --snapshot <dir> [--snapshot-delay <seconds>]
  --perf-log <file>                   once a second, a JSON line: the main thread's CPU use, the longest a ping
                                      waited for it, every wait over 100 ms, what's processing, and frames
                                      presented (with the display awake); see PerfProbe.swift. With it:
                                      --perf-progress (progress reported as an engine does, for --library-demo's
                                      transcribing conversation), --perf-touch (the selected conversation changes
                                      every two seconds)
DAYBOOK_IMPORT_AUDIO=<file>           (environment) imports the file into a new conversation, which processes
```

`.build/debug/Daybook` isn't sandboxed and takes any path. A sandboxed build (docs/sandbox.md) can reach only its
container and, ad hoc, `/private/tmp/daybook/`: `dist/Daybook.app/Contents/MacOS/Daybook --library /tmp/daybook/ui
--snapshot /tmp/daybook/shots`. Any other path stops it at launch with a message naming where it may write.

`--snapshot` renders every visible window to PNG from inside the app, then exits. It works while the screen is locked, when `screencapture` can't. Put flags that take no value last: AppKit reads the arguments as `-key value` pairs, so one in the middle turns the next value into a file to open, and no window appears.
