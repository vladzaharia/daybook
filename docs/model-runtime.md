# Embedded local models

Daybook's `LocalIntelligenceRuntime` runs speech recognition, speaker diarization, and summarization inside the Mac application process, and asks Apple's on-device model (where the Mac has Apple Intelligence on) for titles and vocabulary. Live captions can also run on local models, on the Mac and the iPhone, through DaybookLive ("Live", below); they're tentative and never a transcript. There is no model server, subprocess inference bridge, cloud transcription request, or API key. Model downloads, and update checks the person asks for, are the only intentional networking in this subsystem.

The runtime coordinates three parts described in [Models](models.md): the **catalog** (data: which models exist, their files, capabilities, and licenses), the **store** (files: verified installs under `Models/<engine>/<family>/<variant>/<revision>/`), and the **engines** (code: WhisperKit, Parakeet, Community-1, Nemotron 3, Sortformer, MLX, and Apple Foundation Models). This page covers what the engines do at run time.

argmax-oss-swift is WhisperKit's renamed repository; 1.x vendors its own Hub and tokenizer code, so it no longer depends on swift-transformers. mlx-swift-lm 3.x takes its tokenizer and downloader through protocols and no longer depends on swift-transformers either. Daybook keeps swift-transformers, pinned exactly (1.3.5), for two uses: the model store's downloads (`HubSnapshotFetcher`, `HubApi.snapshot`) and MLX's tokenizer and chat templates (`MLXLocalTokenizerLoader`, a small adapter equivalent to MLXHuggingFace's `#huggingFaceTokenizerLoader` without the Hugging Face client those macros need). 1.3.5 replaced 1.1.6 for its tokenizers: 1.1.6 wrote a literal `▁` for some spaces in Gemma 4's prompts and didn't round-trip its text, and 1.3.5 renders chat templates with `trim_blocks` and `lstrip_blocks` as Hugging Face's own code does (docs/validation.md, "swift-transformers 1.3.5"). It brings swift-huggingface, swift-crypto, swift-asn1, EventSource, and yyjson, and swift-huggingface's `HubClient` under `HubApi`: the store passes `cache: nil`, so a download isn't also kept in the shared Hugging Face cache (`~/.cache/huggingface/hub`), and a file cut off partway starts again (1.1.6 resumed it). Its Xet transport is a package trait Daybook leaves off. mlx-swift-lm's default `FoundationModelsIntegration` trait stays on: it only gates products Daybook doesn't link (`MLXFoundationModels`, `MLXHuggingFace`), Daybook calls Foundation Models itself, and turning the trait off makes SwiftPM and Xcode refuse to update an existing 2.x checkout ("Disabled default traits … on package that declares no traits"). mlx-swift-lm 3.32.3 also brings swift-syntax 603.0.2 into the resolved graph for its MLXHuggingFace macros; Daybook doesn't build that target. FluidAudio's optional NeMo text normalization binary is disabled with package `traits: []`; diarization is included in this release without a trait. Xcode requires the Metal compiler component to compile MLX: `xcodebuild -downloadComponent MetalToolchain` installs it if absent. If `xcrun metal --version` still reports it missing after installation, refresh the lookup cache with `xcrun --kill-cache`.

Available downloads are Parakeet Ultra (632 MB) and Redux (220 MB); Whisper Base, Small, and compressed Large v3 Turbo; the language models below in MLX form; Community-1 speaker models; Nemotron 3 Diarization (offline, 199 MB, compact W8A8, 102 MB, or live, 102 MB); full-precision or compact Sortformer v2.1; and, for live captions, Nemotron 3.5 ASR Streaming (Latin, 588 MB, or multilingual, 615 MB). These limits are capabilities in the catalog (`maxSpeakers`, `voiceEmbeddings`, `expectedSpeakerCount`), which Settings and the pipeline read instead of checking which model is selected.

The Nemotron 3 conversions are pinned at `25a90f97f254428d4b30374b76af9c74fdee8327` of [FluidInference/nemotron-3-diarization-coreml](https://huggingface.co/FluidInference/nemotron-3-diarization-coreml), converted from NVIDIA's general-access checkpoint (2026-09-23) under the [OpenMDW License 1.1](https://openmdw.ai/license/1-1/), whose text ships in `THIRD_PARTY_NOTICES.md`. Parakeet Ultra and Redux are pinned at `95eaa59…` and `8c5ef97…` of FluidInference's Core ML builds of [Moondream's post-trains](https://huggingface.co/moondream/parakeet-ultra) of NVIDIA's parakeet-tdt-0.6b-v3, CC BY 4.0.

The Sortformer conversions are pinned at `ae9a27ab45dc0aa3abede7d2d6bad2b7a69aa6d1`, specifically the `v3` fixed model exports; `engineOptions.precision` says which. The [conversion model card](https://huggingface.co/FluidInference/diar-streaming-sortformer-coreml/blob/ae9a27ab45dc0aa3abede7d2d6bad2b7a69aa6d1/README.md) declares CC-BY-4.0; the [underlying NVIDIA model](https://huggingface.co/nvidia/diar_streaming_sortformer_4spk-v2.1) uses the NVIDIA Open Model License. The Community-1 [artifact provenance and scoped license](https://huggingface.co/FluidInference/speaker-diarization-coreml/blob/df2625ac79a7ac6b65ad868fee6d80f320da4232/NOTICE.md) apply to its supported files. Legacy `wespeaker_v2` downloads were deliberately excluded because that provenance/license scope does not cover them.

Fast, Balanced, and Detailed are **processing presets using the selected weights**, not extra model downloads. Community-1 Fast reuses embeddings for masks with at least 0.95 cosine similarity; Balanced uses upstream defaults; Detailed doubles segmentation overlap (step ratio 0.1 instead of 0.2), lowers the minimum embedded speech span to 0.5 seconds, permits 40 VBx iterations, and re-embeds zero-vote spans. Sortformer uses 4, 8, or 16 seconds of window overlap. More analysis is a compute tradeoff, not a guarantee of improved accuracy. An expected speaker count is a Community-1 clustering target, not a guarantee or a supported Sortformer control. These behaviors use the [pinned FluidAudio configuration API](https://github.com/FluidInference/FluidAudio/blob/v0.17.7/Sources/FluidAudio/Diarizer/Offline/Core/OfflineDiarizerTypes.swift).

Community-1 returns the stable embedding identity `fluid-community1-embedding-df2625ac79a7ac6b` for all presets, read from its catalog entry (`capabilities.voiceEmbeddings.space`). Profiles from unknown or incompatible embedding spaces must never be compared automatically. Sortformer returns an empty embedding dictionary and a nil identity, and reports its limits in warnings. Within-recording clustering and cross-recording matching are separate operations: the app's matching threshold controls whether a compatible voice profile is sufficiently similar to propose an existing identity.

## Download and offline boundary

Downloads are explicit `download(modelID:progress:)` calls, which install a variant's newest catalog revision (or the one named with `@revision`) through `ModelStore`. On the iPhone, files arrive through background `URLSession`s instead (`BackgroundModelFetcher`: one task per file at the pinned commit, resumable, Wi‑Fi only unless cellular is allowed; docs/iphone.md, "Live transcription"), and the store checks them the same way. On the Mac, files arrive with swift-transformers' `HubApi.snapshot`, pinned to each artifact's commit and limited to exactly the files the catalog lists, in `Models/.partial/`, where an interrupted download resumes with the files it hasn't finished (one cut off partway starts again). Each file is then checked against its size and digest from the catalog: SHA-256 for large (LFS) files, the git blob ID for small ones. A mismatched file is deleted so the next attempt fetches it again. The engine checks the assembled install (WhisperKit's tokenizer must parse), a receipt is written, and the folder is renamed into place in one step. Removing a model releases it and removes every revision of that variant and its partial download.

Installs from before the model system (`Models/<catalog ID>/` with an `installed.json` marker) are moved into the store at launch without downloading, after every file is verified in place; see [Models › Storage](models.md#storage).

Inference resolves a model reference to a verified revision, re-checks the receipt and every file's size, and then uses local directory URLs. A job that froze a revision runs exactly that revision or fails; it never runs another. `OfflineWhisperKit` replaces the upstream tokenizer loader because WhisperKit's normal `download: false` flag does not prevent its tokenizer fallback from contacting Hugging Face (still true in argmax-oss-swift 1.1.1, whose `ModelUtilities.loadTokenizer` falls back to a Hub download). The replacement reads the installed tokenizer JSON through argmax's public `AutoTokenizerWrapper.from(modelFolder:)`, with an empty token so nothing is read from the environment, and fails on missing tokens. With a `modelFolder`, WhisperKit's `setupModels` never downloads. MLX is loaded with `LLMModelFactory.loadContainer(from:using:)` from the install's folder: mlx-swift-lm 3.x has no downloader on that path, and its tokenizer comes from swift-transformers with `HubApi(cache: nil, useOfflineMode: true)`, which only reads files. Apple Foundation Models runs on the device through the system framework; Private Cloud Compute is never used. Speaker models are loaded directly through `MLModel(contentsOf:)`, bypassing FluidAudio's automatic cache-repair/download path.

Digests are checked when a revision is installed or migrated; before each load only file sizes are re-checked, so a same-length modification made afterwards isn't detected until the next install. The built-in catalog ships inside the signed app; the person's `UserModels.json` (models they added, updates they installed) is not signed. Model repository locations come from the catalog; recording contents are never used in URLs. Network blocking at the process or OS level remains a useful independent verification of offline behavior.

## Processing

One application-owned runtime actor serializes expensive operations and prevents deletion during active work: loaded revisions are leased, so neither removal nor garbage collection takes them. At most one model is loaded per role. MLX is an exclusive engine: loading the language model releases the speech and speaker models, and loading either releases the language model. MLX's retained allocation cache is capped at 256 MB and cleared when the language model is released. `unload()` releases all retained model references. Models Daybook holds itself are also released once nothing has used them for two minutes (`idleUnloadDelay`; back-to-back jobs keep them), and at once when macOS warns that memory is short (a memory-pressure source; a running job finishes first), so the always-running app doesn't keep a language model of up to 34 GB resident. Models the system holds (Apple Vision, Apple Foundation Models) stay. A cancelled task is checked between downloads, speech slabs, synthesis passes, and output tokens. Native Core ML prediction and clustering may finish their current operation before cancellation returns.

Speech recognition uses word timestamps and five-minute PCM slabs with one second of context at each edge. Small streaming conversion buffers and 64-bit source frame positions avoid loading the original file into memory or overflowing a 32-bit frame count on very long recordings. Midpoint ownership assigns overlap words to one slab, bounding decoded-audio memory and reducing boundary loss. The approved glossary conditions Whisper's decoder prompt. Whisper's built-in VAD chunking runs within each slab. Word probabilities are model estimates, not calibrated certainty. Speaker detection uses FluidAudio's disk-backed file API and returns anonymous speaker turns plus embeddings. It does not claim that a cluster is a named person or automatically merge identities across unrelated recordings.

Sortformer reads 30.72-second windows with surrounding STFT context and aligns its four output columns using overlapping activity. Decoded PCM and mel features stay bounded; the four final probability tracks use approximately 0.72 MB per hour. A silent overlap cannot prove identity continuity and can cause a speaker swap. This mode exposes that limitation and does not fabricate reusable voice embeddings. Both speaker pipelines create fresh per-run processing state so changing presets cannot reuse a previous run's clustering settings.

Parakeet transcribes through FluidAudio's `AsrManager`: recordings longer than 30 s are converted to 16 kHz once, read from disk, and decoded in 15 s windows with FluidAudio's seam handling, so memory stays flat. Sub-word token timings and confidences become words and passages (docs/models.md). It takes no vocabulary prompt, so the glossary doesn't reach it; a chosen language reaches it as a script hint. Its confidences are the decoder's token probabilities, which are high on clear speech (0.99 mean on the synthetic fixture) and low on speech it can't transcribe (0.36 on Japanese), and like Whisper's are estimates, not calibrated certainty.

Language routing runs before speaker detection (docs/models.md, "Routing"): with Automatic, a transcript that reads as a language the model doesn't cover, or as no clear language at low confidence, is transcribed again with the other-languages model, whose own detection decides which transcript is kept and recorded.

Nemotron 3 reads the recording in 30 s blocks through one converter into FluidAudio's streaming diarizer and turns the 10 ms speaker probabilities into turns as they arrive, so neither audio nor probabilities are held for the whole recording. When a speaker model's capabilities declare no voice embeddings, the pipeline runs the voice-profile model on its turns (`EmbeddingVoices`, routed by `ModelRouting.voiceEmbedder`): Community-1 embeds each speaker's solo speech with its WeSpeaker model and averages it, in Community-1's own embedding space.

Summarization uses the selected local language model (Gemma 4 by default) and a fresh chat session for each pass, with thinking off where the variant says so (`engineOptions.thinking`; any thought block that appears anyway is removed). It counts model tokens, extracts evidence from long transcript and note chunks, and recursively compresses evidence until the final prompt fits a conservative context budget. This processes the entire input instead of truncating the end. Multi-pass summaries carry an explicit detail-loss warning. Transcript text, notes, and glossary are serialized as source data, and system instructions reject commands embedded inside them. This reduces prompt injection risk but is not a formal guarantee against model error.

The model selects the meeting kind when the user chose Automatic, then emits a title, overview, sections, explicit actions, and proposed glossary terms. A focused second generation pass extracts assignments with supporting source quotes; quotes are matched against the original conversation with whitespace, case, and timestamp formatting normalized. Ungrounded quotes are rejected, and names absent from the supporting quote are not assigned as owners. This does not prove that a model's interpretation is correct, and users should review their actions. A user-selected kind is preserved. Terms absent from the transcript or notes are filtered out. Model output is never executable. Therapy guidance is limited to reporting the conversation: no invented diagnoses, advice, or commitments. When the variant declares `structuredOutput`, the final pass and the action pass are constrained to JSON Schemas (`MeetingSynthesis.summarySchema`, with "kind" limited to the chosen kind or any but automatic, and `actionSchema`) through mlx-swift-lm's XGrammar-backed guided generation, which samples greedily, as the free-form passes do at temperature 0. The grammar only masks tokens; its fast-forward of forced text is off, because re-encoding that text derailed Gemma 4 E2B (docs/validation.md). If constrained generation fails or its reply doesn't parse, the same prompt runs free-form and is parsed as before. Structured parsing failures preserve the real model response with a warning, allowing the user to review it or retry with a larger model. When Apple Foundation Models is available and selected for small tasks, it chooses the title, an automatic kind, and vocabulary suggestions from a bounded excerpt before the summary is written ([Models › Small tasks](models.md#small-tasks)); otherwise the summarizer does, as before.

Custom template instructions affect focus and section structure while preserving the output schema and faithful-source rules. Their first 700 model tokens are used, with a warning if truncated. Notes and bookmarks travel inside the transcript at their times (`SummarySource`; [templates](templates.md#notes-and-bookmarks)): each extraction pass sees the notes in its part and, when they fit in 1,500 tokens, every note for reference; compression keeps facts tied to their labels; and the final pass gets the notes themselves plus up to 1,400 tokens of verbatim passages near them, chosen nearest first for every note before any gets more. Written notes, even timestamped notes, remain user context rather than spoken quotations. The final action verification pass accepts source quotes only from the recorded transcript, never from a note.

## Live

Live captions (docs/capture.md, "Live captions"; docs/iphone.md, "Live transcription") run on local models when they're downloaded, on the Mac and the iPhone. They stay what live captions always were: tentative feedback, saved on the device that made them, never synced, fused, summarized, or used as evidence. Final transcription, speaker analysis, and summaries stay with the Mac's processing models above.

```text
 capture tap ──► SpeakerLabelledCaptioner ──┬─► words: LocalStreamingCaptioner (Nemotron 3.5 ASR Streaming)
  (append: enqueue only)                    │          or the system's SpeechCaptioner when not downloaded
                                            └─► speakers: Nemotron 3 live (fast32, 2.88 s behind)
                                                 └─► solo stretches ─► WeSpeaker ─► known voices ─► names
```

- **One protocol.** Every piece is a DaybookCaptions `LiveCaptioning`, so the Mac's `LiveCaptionsController` (You and Call), the iPhone's, and a recorder's Listen Live use them unchanged. `LiveCaptioners.captioner(models:locale:backlog:timelineOrigin:fallback:)` composes them from what's installed (`LiveModelSet`): words from the local recognizer when one is installed and covers the captions' language, else from `fallback` (the Speech framework, as before); with a live speaker model, captions labelled with speakers; with the voice-profile model and known voices, names.
- **Words.** `LocalStreamingCaptioner` feeds 16 kHz mono (`LiveResampler`, one `AVAudioConverter` that keeps its state and mixes channels down) to `StreamingNemotronMultilingualAsrManager` in half-second batches; the model decodes 1.12 s (Latin) or 2.24 s (multilingual) chunks, and a cache-aware RNN-T never revises a token. `LiveTranscriptBuilder` merges SentencePiece pieces into words and words into passages that close at a sentence's end, a 0.8 s pause, or 12 s; the open passage is tentative and keeps its ID as it grows. Pauses are judged only up to 2.5 s behind the audio fed (`decodeLag`), so a word still being decoded doesn't split its passage. The language prompt is the captions' locale ("de-DE"); a locale the model's table lacks runs with automatic detection.
- **Vocabulary.** The recognizer is biased toward the library's approved vocabulary (`LiveVocabulary`: Settings › Vocabulary's approved terms, each spelling once, at most 500), through FluidAudio's decode-time biasing (`StreamingNemotronMultilingualAsrManager.setCustomVocabulary`): at each step, tokens that continue a term get a flat log-probability bonus (4.5, FluidAudio's default; terms under three letters are skipped). The apps keep it current from the library, and each running capture applies a change before its next half second of audio, so a term approved mid-recording helps the rest of it. Proposed terms stay out until approved. The system's recognizer (the fallback) isn't biased.
- **Speakers.** `SpeakerLabelledCaptioner` wraps any captioner. The same audio goes to `Nemotron3Diarizer` with the `fast32-split-w8a8` preset (32-frame chunks, 2.88 s latency, 8 slots, split graph on the Neural Engine). `LiveSpeakerTimeline` turns 10 ms probabilities into runs per slot (active above 0.5, gaps under 0.3 s bridged), keeps 15 minutes, and finds solo stretches (exactly one slot active, 1.5–10 s). Each caption is labelled with the slot that spoke most of it ("S2"). Streaming Sortformer keeps a speaker cache, so a slot stays with its voice for the capture.
- **Names.** Each solo stretch is cut from a 24 s ring of the fed audio and embedded with `WeSpeakerEmbedder` (Community-1's FBank and WeSpeaker ResNet34, the same code the Mac's final pipeline uses for voice profiles, moved to DaybookLive so both share it), so the vectors are in `fluid-community1-embedding-df2625ac79a7ac6b`. `LiveVoiceIdentifier` keeps each slot's newest eight embeddings, averages them by duration, and, once a slot has 3 s embedded, compares the average with known voices in the same space (the best of each person's embeddings, cosine). It names a slot only when the closest person reaches `SpeakerMatchingConfiguration`'s 0.82 and leads the next by 0.06, and when two slots claim one person only the clearly closer keeps the name.
- **Known voices** come through `KnownVoiceSource` (DaybookKit). Both apps use `KnownVoices.fromProfiles`: each speaker profile's voiceprints in the voice-profile model's space (the person's names and what Daybook learned since), newest sixteen. Profiles sync with the library, so a Mac's reach the iPhone and compare there because both run the same embedding model.
- **Never in the capture's way.** `append` only enqueues (`LiveInput`, a bounded `AsyncStream` that drops the oldest audio and reports how full it is); recognition and speaker detection run on their own detached tasks at utility priority, each with its own queue; a model that can't load or fails ends only that part (no words: `.failed`, as before; no speakers: unlabelled words). The models load on the Neural Engine and CPU, never the GPU, which a locked iPhone can't use.
- **Backing off** (`LiveLoadPolicy`, applied by `LiveLoadGovernor` with hysteresis): speakers go first, under Serious heat, Low Power Mode, a battery under 20% unplugged, or a backlog over half full (until it drains under a fifth); words stop (audio let go, captions resume with a gap) at Critical heat or under 10% unplugged. Out of sight (the iPhone app in the background) speakers go on at a lower cadence (`LiveWorkLevel.reduced`, `whenHidden`): the speaker model hears the audio four seconds at a time, and only voices not yet named are embedded. The Mac reads heat and Low Power Mode; the iPhone adds its battery and whether it's in front (`PhoneLiveConditions`).
- **Speakers afterwards** (`LiveSpeakerPass`). A caption the speaker model didn't hear (shed, or the model failed) is saved with `needsSpeaker`. When the iPhone app is next in front and not recording, `LiveCaptioners.labelSpeakers` reads the filed recording (16 kHz, a second at a time, off the main actor at utility priority) through the same speaker and voice-profile models, from its start, and labels every caption from that one run: slots from two runs can't be mixed, and a run that heard everything is at least as good as the live one. The recording, not the 24 s audio ring, because a shed stretch is usually longer than the ring. Leaving the screen cancels it; it starts over next time. The words are never touched.
- **Memory.** `LiveModelHost` loads each model once and shares it between captures (the Mac's You and Call share one recognizer and one speaker model; each capture gets its own decoder state and its own `Nemotron3Models` buffers over the shared Core ML model, which two streams must not share), leases the revisions in the store while loaded, and releases them when the last capture ends: after two minutes on the Mac, at once on the iPhone. The live models are loaded beside the recording, not through `LocalIntelligenceRuntime`, so captions never wait behind a processing job and processing never waits for them. Resident sizes are about the downloads: the recognizer's encoder is 6- and 8-bit (566 MB), the speaker model W8A8 (99 MB), WeSpeaker 26 MB.
- **Where.** `DaybookLive` (FluidAudio, DaybookCaptions, DaybookModelStore; no MLX, no WhisperKit) and `DaybookModelStore` (the store and downloads, split out of DaybookIntelligence and re-exported by it) build for macOS and iOS; the iPhone links only these. The Mac registers `NemotronStreamingEngine` (live transcription) in `ModelEngineRegistry.standard` so Settings › Models downloads, checks, and removes it like any model; the runtime never loads it.

```swift
    // update.fraction and update.message; hop to MainActor for UI changes.
}
let speech = try await runtime.transcribe(url: audioURL, model: "whisper/base", glossary: ["Daybook"])
let speakers = try await runtime.diarize(url: audioURL, model: "community-1/offline",
    options: .init(quality: .accurate, expectedSpeakerCount: 2))
let notes = try await runtime.summarize(
    transcript: timestampedTranscript,
    notes: handwrittenNotes,
    template: .auto,
    glossary: approvedTerms,
    model: ModelReference("qwen2.5/1.5b-4bit", revision: frozenRevision),   // a queued job's exact revision
    templateInstructions: "Use a Reflections section when supported.",
    highlightEvidence: highlightedTranscriptExcerpts
)
try await runtime.remove(modelID: "whisper/base")
```

References accept variant keys, legacy catalog IDs (`"whisper-base"`), and `"key@revision"`. `RecognitionResult` retains timed segments, words, confidence estimates, language, and duration. `SpeakerAnalysis` contains turns, embeddings, their optional model-space identity, and warnings. `GeneratedMeetingNotes` contains the `MeetingSummary`, proposed terms, raw response, and warnings. Each carries the `ModelProvenance` that produced it (family, variant, revision, engine, and engine version), which `InferenceProcessingEngine` stores in the result's `ProcessingSettings.model`. The application layer owns persistence, corrected transcript history, cross-recording fusion, speaker names, and approval of learned terms. The runtime does not modify model weights or silently learn from sensitive conversations.

The model manager builds on `inventory()`, `diskUsage()`, `collectGarbage(protecting:)`, `addModel(_:client:)`, `removeAddedModel(_:)`, `checkForUpdates(client:)`, `installUpdate(_:)`, and the store's pins and leases.

## Verification

Normal unit tests must not download model weights. Store, migration, update, and engine tests use synthetic files with real digests, a fake fetcher, and a scripted Hugging Face client; installation rejection and structured-output parsing are tested without inference. A separately invoked smoke test should explicitly download the smallest models, transcribe a known local fixture, run speaker detection, and generate a summary through these same APIs. Repeat that smoke test with network access denied after installation to verify offline loading. Accuracy, overlapping speech, diarization error, very long sessions, multilingual audio, and machine sleep require representative recordings beyond a basic smoke test.

The implemented diagnostic runs without creating a meeting in the library:

```sh
swift test --filter 'IntelligenceTests|ModelStoreTests|ModelMigrationTests|ModelEngineTests|ModelAdditionTests|StructuredOutputTests|SmallTasksTests|SpeechEngineTests'
swift run -c release Daybook --smoke-test --summary-model gemma-4/e2b-4bit --download-models --output /tmp/daybook-smoke.json
swift run -c release Daybook --smoke-test --summary-model gemma-4/e2b-4bit --output /tmp/daybook-offline-smoke.json
swift run Daybook --smoke-test --skip-summary --transcription-model parakeet/ultra \
    --speaker-model nemotron-3-diarization/offline --models /tmp/daybook-models --output /tmp/daybook-speech.json
swift run Daybook --evaluate ~/Recordings/eval --presets quick,balanced,detailed --output /tmp/daybook-eval.json
```

`--download-models` explicitly installs the default Whisper, selected language, and speaker models in the library's Models folder, after migrating any older installs there. That's the running build's library: `swift run` and other unbundled runs use `~/Library/Application Support/Daybook Development`, never the app's, and a sandboxed app uses its container's (docs/sandbox.md). Omit it to require an existing installation. `--summary-model gemma-4/12b-4bit` tests a stronger model; without that flag, the machine's recommended default is used. Model flags accept variant keys or the older catalog IDs (`qwen-7b`). `--transcription-model` overrides the Whisper choice. `--models /path/to/models` overrides that folder; `--audio /path/to/meeting.wav` replaces the synthetic fixture. Without `--audio`, the diagnostic uses macOS `say` to generate an audio file in a temporary directory, then runs the actual embedded inference pipeline. Exit code 0 requires recognizable fixture words, detected speech turns, and a structured summary with the core milestone and correctly assigned checklist task. This system speech subprocess exists only in diagnostics; it does not perform app transcription, diarization, or summarization.

`--skip-summary` checks transcription and speaker detection only, so no language model is needed. `--language de` passes a transcription language. When the speaker model makes no voice profiles (Nemotron 3), the diagnostic runs the voice-profile model on its turns if it's installed, or the one `--voice-model` names (downloaded with `--download-models` only when named), and requires finite 256-dimensional embeddings; the report records the transcription model that ran, its language, word count and mean confidence, and the transcription and speaker-detection times. `--evaluate` scores recordings with references instead; see [Validation › Evaluating speech models](validation.md#evaluating-speech-models).

`--speaker-model sortformer-2.1/fp16` or `--speaker-model sortformer-2.1/compact` selects a different speaker download; `--speaker-model none` skips speaker detection. The report records `transcriptionSeconds`, the summary's provenance, `summaryStatistics` (model load time, prompt and generation tokens and tokens/s for free-form passes, and constrained passes timed whole), and, when the Mac has Apple Intelligence on, the small-tasks title, kind, terms, and time (`smallTasks`; reported, never required). `--speaker-quality fast|balanced|accurate` exercises the processing presets and `--expected-speakers 2` requests a Community-1 clustering target. The report records speaker model, quality, and embedding identity/count. When the speaker model declares voice embeddings, the diagnostic additionally requires finite 256-dimensional voice embeddings.

`--notes-highlights` adds the actual built-in Planning template, a timestamped private note, and highlighted recorded evidence to the generated fixture. It requires the speaker-detection blocker as well as the milestone and Alex's assignment in the model output, and rejects repeating the private note instruction as conversation content. The flag is ignored for external `--audio` fixtures.
