## Notes on partial fixes

- **MSQ-07:** ProcessingRequest.FailureKind covers noSpeech, modelsMissing, modelCouldNotStart, cloud(badKey/noCredit/modelUnavailable/offline/rateLimited/busy/connectionLost/other), recordingDidNotStart, plainReason and other. It is persisted on Outcome.failure through ExtensibleOptional, so an unknown kind reads as other and its raw value is written back. failed(by:at:reason:kind:) takes it. The ProcessingFailureClassifying protocol is adopted by DaybookError, AudioFetchError, LocalIntelligenceError and CloudError. The legacy-message fallback now matches only the sentences written for each kind, so iCloud download errors no longer read as missing models. ProcessingStatus.Failure.kind and isNoSpeech, plus FailureWords(title, message) with the device named and one 'The recording is saved.', are in DaybookKit. Tests: FailureWordsTests. Partial because a failure kept only on Meeting.errorMessage (the Mac's own job with no request) still has no stored kind. It reads through the stricter fallback, because storing it needs a field in Meeting/MeetingMerge (Models.swift is outside this package). Wave 2 still has to pass kind: where errors are caught (AppState.finishRequests, PhoneProcessor).
- **MSQ-14:** Removed: TypeStyle.panelTitle and panelTime, MeetingKind.looksLike, AppState.removeModel, SpeechEvaluation's werRate, and the AppState.errorMessage setter (the getter stays). `environment` is now a let. AppState.showNotes calls FloatingNotesWindow.shared directly, so nothing uses NotesPanelController any more. View.topBar is kept for w2-transcript-page. Two items are in other packages' files, so they're left to their owners: NotesPanelController in NotesPanel.swift (w2-recorder-surface should delete it) and ModelSize.physicalMemoryGB in ModelPresets.swift (w2-models-processing should delete it).
- **MSQ-15:** New Sources/Daybook/App/SettingsPane+Opening.swift adds SettingsPane.storageKey and open(with:defaults:activating:). The debug --open-settings flag uses it. AppState.Preference now names every preference key AppState, DaybookApp, and LibraryDemo use. AppState+Phone uses ReplicaIdentity.Key.linkDeviceID (2-line edit in a file outside my paths). w2-link-pairing's branch already adds the LinkCapabilities feature constants. Raw 'settingsPane' writes and reads in other packages' files are left for the integrator: SettingsView.swift:15, ConversationPage.swift:247/393/528 (SettingsPaneKey and the raw 'models'), MenuBarView.swift:64, FloatingNotesView.swift:456, PhoneDevicePage.swift:63, DeviceComponents.swift:307 (raw 'devices'), and DevicesSettingsPane.swift:269. GeneralSettings' @AppStorage("showsFloatingNotesWhileRecording"/"showsMenuBarExtra") should use AppState.Preference.
- **MSQ-21:** MultiSourceRig now builds AppState with a fake CaptureEnvironment, and its defaults turn off call audio, live captions, and the panel. New rig methods startRecording(), stopRecording(), and storeMacRecording() drive AppState's real start and stop. The copied macStartsRecording, macStopsRecording, and storeMacRecording are gone from CascadingRecordingTests and MacFirstMultipointTests; those tests now run through the real Record and Stop, their phones are torn down with addTeardownBlock, and a stop's notice is waited for with waitUntil.
